# Performance Audit Report

## User Need

用户希望基于当前 Vue + Electron 项目的真实代码和现有 E2E 能力，反复验证启动、关闭和关键功能路径，找出当前项目中所有可疑的性能点，并输出一份不能靠猜测、每一项都包含具体代码定位和逻辑证据的性能优化报告。

## Goal

产出一份中文性能优化报告，覆盖启动、关闭、主进程 Presenter、IPC/事件、renderer/Vue、数据库/文件/插件/MCP、E2E 覆盖到的关键用户路径，并对每个可疑性能点给出：

- 现象或触发路径
- 代码定位（文件与行号）
- 逻辑链路说明
- 验证方式或可复现证据
- 风险级别和优化建议

## Acceptance Criteria

- 报告保存到 `docs/issues/performance-audit-report/report.md`。
- 每个列为“可疑性能点”的条目必须包含至少一个当前代码位置引用，且说明为什么该代码会进入性能热点或生命周期风险。
- 报告必须区分“已由 E2E/命令验证的事实”和“静态代码审计发现的风险”；没有证据的内容不能写成确定结论。
- 启动和关闭路径必须至少通过现有 E2E 或等价命令实际运行验证一次，并记录命令、结果和关键输出。
- 需要覆盖现有 E2E smoke 能力能到达的主要窗口/路由：主聊天窗口、Settings、browser route、readonly settings/routes、agent CRUD、workspace watcher。
- 若某些验证因环境、凭据或运行时间限制无法完成，报告必须明确列出缺失证据和原因，不把缺失项伪装成已验证。

## Constraints

- 不修改产品逻辑，只做调查和报告。
- 不记录、导出或暴露用户密钥、token、凭据或本地私密数据。
- 使用当前 worktree 作为事实来源；不能依赖记忆或未检查的上下文。
- 遵守现有 E2E 默认行为：默认使用临时 `DEEPCHAT_E2E_USER_DATA_DIR`，避免破坏用户真实数据。

## Non-Goals

- 本任务不直接实施性能优化代码改动。
- 不引入新的遥测或长期运行的 profiling 基础设施。
- 不声称覆盖所有无法由当前环境启动或凭据触达的第三方服务调用性能。

## Open Questions

- 无。报告位置采用本仓库 SDD 约定；无法验证的外部依赖会在报告中显式列为证据缺口。
