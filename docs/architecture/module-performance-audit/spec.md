# Module performance audit

Audit date: 2026-09-07. Source baseline: `dae1e405e1ecef9dffe26d241463753ac125238d`
(`dev`). Environment: macOS arm64, Node 24.18.0, pnpm 10.34.5, Electron 41.10.4.

## Scope and decision rule

Every application module below received one ownership, caller, resource-lifecycle, user-workflow,
and test review. Rendering/CPU, database/filesystem I/O, IPC, and network work were inspected where
applicable. A synchronous API, slow test, large file, or documented follow-up alone does not prove a
product bottleneck. Repairs require a redundant operation on a real path, a reproducible failure,
or measured resource use, while preserving observable behavior and persistence/security contracts.

The product repairs remove duplicate work or forward existing cancellation. Required full-context,
export, schema validation, permission, and durable journal operations remain intact. There are no
new dependencies or interface layout changes. Each independent repair has one commit on a separate
`codex/` branch from the source baseline and a PR targeting `dev`.

## Validation

The baseline production build passes. Its complete Playwright smoke run reports 32 passed,
5 existing live-provider skips, no failures or flaky tests, in 194.146 seconds. This duration is
test execution cost, not an application performance measurement.

The combined portable main suite passes 8,432 tests, with 485 cases skipped by native or platform
conditions. The additional Electron-native selection passes 687 tests in 48 files, with four VSS/Windows
skips. Across the two runs, 8,912 distinct main tests pass; five remain conditional: two VSS
fixtures, two Windows/VSS cases, and the separately invoked crash-worker fixture. The final combined production build passes all 33 local E2E workflows, with five existing
live-provider skips, no failures, and no flaky tests (265.182 seconds). Format, i18n, lint, and
node/web typechecks pass. The normal catalog refresh also passes 44 provider/model/package and
architecture-baseline tests. Each individual repair already passes format, i18n, lint, typechecks, and its relevant
behavioral suite. Renderer test maintenance passes the complete 2,377-test renderer suite.

The combined native memory/performance configuration passes all six files / ten tests. On its fixed native
fixtures, a 100k-row Tape range read has a 0.0405 ms median; the intentionally complete view takes
130.567 ms. Adding 0 / 10k / 100k unrelated global trace rows does not increase the bounded message
history median (0.285 / 0.287 / 0.267 ms). Clearing 10k rows uses 40 batches with a maximum measured
transaction of 5.700 ms. These checks preserve their existing dataset and transaction budgets.

A settings-navigation timeout occurred during a full E2E run with concurrent heavy test/check
work. Three isolated repetitions and the final isolated complete smoke pass without changing
that navigation test or its timeout. The cause of the contended timeout is not established.

## Rendering evidence and limits

A temporary production-Electron probe streams 49,720 bytes of Markdown with 120 sections, lists,
and code fences through a local HTTP provider, in 450-character chunks every 25 ms. During the
run, typing remains accepted and the composer draft survives completion. The measured input
roundtrip is 7 ms, rAF p95 is 33.4 ms, maximum frame gap is 117 ms, and two long tasks take 68 and
61 ms. Peak DOM count is 5,384; final DOM count is 3,204. The 186-frame sample includes first-use
Markdown worker startup and DOM-count instrumentation.

This sample does not establish a 60/120 Hz performance guarantee or attribute the long frames to a
specific removable operation. The temporary profiler is excluded from regression tests; the durable
local streaming test checks user-visible editing and completion without timing-sensitive budgets.

Live provider connectivity, persistence against a real provider, physical trackpad behavior,
Windows/Linux packaging, signed CUA installation, native OCR execution, Browser PiP latency, and
large encrypted-backup scaling are not established by local macOS smoke or mocked seams. Their
active acceptance records remain. Long-session workspace-cache growth, orphaned draft-storage cleanup, and OCR identity/admission
changes need workload measurements and compatible persistence/lifecycle contracts before a
performance repair. For example, OCR currently prepares the effective engine before reading an
engine-keyed cache; skipping that work without a trustworthy identity could reuse an incompatible
artifact. Those follow-ups are not reported as resolved product bottlenecks.
